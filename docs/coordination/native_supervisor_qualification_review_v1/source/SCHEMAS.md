# Closed source interfaces and retained outputs

All of these are prospective; no request/admission/result is instantiated by the author. FilePin is exactly `{path: string, bytes: integer, sha256: lowercase hexadecimal string}`. Captured state is `[st_dev, st_ino, st_mode, st_nlink, st_size, st_mtime_ns, st_ctime_ns]`. JSON input rejects duplicate keys and nonfinite constants through protocol decode; all writes use ASCII sorted compact JSON with one final LF and exclusive creation. Source manifest metadata is itself pinned opaque input and need not use the compact layout.

`ri171-one-case-request-v1` has exactly seven fields:

- `schema`: the literal schema string.
- `case_id`: one exact literal ID from CASE_MANIFEST.json.
- `operation`: a fresh immediate child of the fixed evidence root, prefix `ri171-supervisor-case-`.
- `sources`: exactly `protocol`, `driver`, `worker`, `payload`, `checker`, `manifest`, `subject`, each FilePin. Role paths are fixed by protocol.py, including the immutable external RI169 subject.
- `source_admission`, `bootstrap_preflight`, `outer_contract`: three genuine root-created records bound by FilePin. Their bytes are checked; authority, current supplier/host applicability, exact external deadline and actual completion provenance are external root requirements. A schema-shaped fabricated body cannot self-authorize an operation.

Captured custody has exactly `request`, `request_state`, `sources`, `prerequisites`. Each role/prerequisite observation is `{pin: FilePin, state: captured state}`. Each complete before/after observation must match. The independent tail reader retains errors for every comparable source/prerequisite even if another read fails.

A successful collection has exactly22 fields: `schema`, `case_id`, `status`, `before`, `after`, `command`, `environment`, `cwd`, `worker_pid`, `worker_returncode`, `worker_reaped`, `errors`, `body_tree`, `subject_deadline_seconds`, `controller_collection_timeout_seconds`, `new_subject_cleanup_budget`, `start_monotonic_ns`, `worker_stdout`, `worker_stderr`, `case_report`, `trace`, `end_before_final_record_monotonic_ns`. Schema is `ri171-one-case-collection-v1`; successful status is `CAPTURED_FOR_INDEPENDENT_SAVED_REVIEW`, never qualification acceptance. Each worker stream stores `{pin,state}`. Worker exit/reap must be actual; missing timeout completion is not invented. Failed partial collections may lack unavailable artifact fields and may have `external_recovery_required:true`; these never satisfy the successful envelope. First and secondary errors are ordered `{stage,type,message}` records. Final receipt write/close and outer return are outside the saved pre-write timestamp and require genuine outer evidence.

`ri171-case-observation-v1` has exactly15 complete fields: `schema`, `case_id`, `before`, `source_subject`, `entry`, `fault`, `return`, `exception`, `worker_errors`, `journal`, `recovery`, `entry_start_monotonic_ns`, `entry_end_monotonic_ns`, `after_sources`, `body_tree`. An exception is null or `{type,message}`. `return` is the actual target return or null on escape; it is not an expected answer. Worker errors use `{stage,type,message}`. An observer journal preserves each complete original11-field record including both raw stream hex strings and all source first/secondary errors. Whole cases retain the original17-field RI169 receipt, with original RI165 schema/version label, not a rewrapped success verdict.

A trace is a finite ordered list with `event`, actual `monotonic_ns`, and the exact event-specific fields closed in `check_saved.py`'s `shapes` table. The write event has precisely `{tag,requested,written}` with optional explicit `injection`. Every saved operand is copied before mutation. The event table covers actual read/write/acquisition/registration/close/poll/kill calls, named doubles, separately declared fixture-directory sync, source errors and exact serialized receipt candidates. A timestamped double is still a double, not a current OS observation. There is no arbitrary event-schema fallback.

Recovery rows for actual owned handles contain `{kind,pid,returncode,reaped}` or `{kind,pid,error}`. A separate leaf row either records its actual observed identity and a kill attempt, or its unavailable/failed identity; every leaf row retains `requires_external_recovery_review:true`. A kill attempt has `absence_proven:false`. Failed/unknown/not-reaped rows cannot become evidence of subject or descendant cleanup. Root resolves them with genuine separately authorized evidence.

The exact top-level operation namespace after a complete capture is six files plus the `body` directory: `REQUEST_CAPTURE.json`, `worker.stdout`, `worker.stderr`, `CASE.json`, `TRACE.json`, `COLLECTION.json`, `body`. The complete body namespace consists only of the literal named leaves in `check_saved.py`, including explicitly retained path/descriptor replacement originals; no symlinks or unexpected directories are admitted. The full tree records each file as `{path,kind,bytes,sha256}` (directories, where administratively represented, are `{path,kind}`). Whole body membership and file identities are compared between worker capture, real child-exit collection and independent saved review, with a final read-set/tree recheck.

The saved oracle output schema is `ri171-independent-saved-case-check-v1`. Its exact fields are `schema`, `status`, `case_id`, `checks`, `read_inputs`, `entry_duration_seconds`, `monitor_review`, `external_recovery_obligations`, `saved_observations_only`, `subject_reexecuted`, `authorship`, `qualification_acceptance`, `native_or_scientific_acceptance`. Checks contain `{id,passed}`; read_inputs are exact FilePins for complete artifacts read. Status always retains root genuine-origin review, and additionally recovery review where applicable. Both acceptance flags are false. A failed oracle raises, saves no fabricated success and leaves existing evidence untouched; root retains its actual failure transcript.

No aggregate success is synthesized by this packet. Root must reconcile all92 exact case IDs, same source closure, exact per-case checks, genuine tool evidence and all recovery obligations before accepting the finite supervisor qualification. Missing IDs, different source pins or earlier-unrelated failures cannot be replaced by counts, inherited recipes or driver labels.

`monitor_review` distinguishes complete independently parsed durable whole-supervisor ps records, failed journal writes with retained complete serialization candidates, deliberately mutated journal files with no complete monitor credit, and non-whole cases. It never repairs or invents damaged journal bytes. Negative late-I/O qualification can verify the exact failure while retaining that explicit custody loss.
