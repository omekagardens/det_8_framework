The final scan first retains the complete raw namespace. Allowed-name/type

For a captured expected list beginning with the exact directory-root record,
the complete normalized tree is compared byte-for-byte through canonical JSON
with that whole expected list. A missing root gives an empty selected list;
missing/extra descendants, changed hashes/bytes, type and symlink targets all
remain differences. Nothing grants equality from merely visiting the root.
The prior separately registered fixture tails remain unchanged and still execute
before this final scan. Their successful older observations are retained even
when this later one differs.

An absent or incomplete expectation is explicitly marked unavailable. If no
primary error exists, it refuses with `complete captured control fixture
expectation <root>`, ensuring a nominally successful controls action cannot omit
its complete expected trees. Following a prior primary error, it retains the
partial final observations and marks comparisons unavailable; it does not
invent expectations, claim equality or erase the earlier failure. Available
expectations are still compared after an earlier primary error. Invalid extra
keys in a returned fixture map remain refused by the unchanged independent
fixture-tail closed-map checks. Trusted production actions return the actual
complete trees, not request-selected expectations.

All comparable member, ordinary-output and fixture mismatch records are saved
before the first accumulated error is raised. Ordering is original structural
member errors, then sorted ordinary-output errors, then fixed-order fixture
errors. `I.tails` keeps any earlier primary error. A structural error therefore
cannot suppress available fixture reconciliation, and an earlier ordinary-file
mismatch cannot hide either fixture mismatch. Unsupported/special or unbounded
filesystem members that prevent the original tree scanner from returning still
refuse at that unchanged scanner; no complete final tree is claimed in that case.
