# Source-level comment on the proposed root outer deadline

Root proposed the fixed outer prefix `/usr/bin/env -i` with the exact RI137 environment, then `/usr/bin/perl -e 'alarm 960; exec @ARGV; die $!;'`, followed by the exact `/usr/bin/python3 -I -B` launcher argv. This note reviews that literal proposal only; it is not a command invocation, runtime observation or source edit.

The primitive is suitable for a **parent-process timeout** under root's authenticated supplier/host and signal premises. Apple's Darwin execve documentation explicitly includes interval timers among inherited process attributes. Its signal discussion also matters: ignored signals and the blocked mask survive exec, whereas caught dispositions reset. Root must retain an applicable unblocked, terminating SIGALRM premise, rather than infer it from an empty environment. [Apple execve manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/execve.2.html).

Perl's alarm requests SIGALRM for its own process after the chosen wall-clock interval. Scheduling can delay delivery, so it is not a hard real-time scheduling guarantee. [Perl alarm documentation](https://perldoc.perl.org/functions/alarm). Apple's alarm manual likewise identifies the calling process as the recipient. [Apple alarm manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/alarm.3.html).

For the proposed multi-element argv, `exec @ARGV` uses the argument list directly; it does not join/reparse this vector through a shell. Successful exec replaces Perl, while `die $!` handles an exec failure. Root still needs correct literal shell quoting for the initial tool command and exact full command retention. [Perl exec documentation](https://perldoc.perl.org/functions/exec).

The alarm begins in Perl before replacement, so it covers the Python launcher's preownership authentication, source load, child operation, tails and final writes. It does not time earlier env/Perl startup. Preserve actual full outer timing and do not describe the alarm alone as a measurement of all tool overhead.

The timer does **not** provide group cleanup. RI135 child_run creates a separate session for the control child. If the parent receives a terminating SIGALRM while that child is alive, the parent's Python finally blocks may not run and the child can survive. Root must retain the failed attempt and handle identification/cleanup of any actually surviving owned child under genuine process evidence. A timeout cannot be called accepted completion or complete failure-tail custody merely because the parent ended. No group RSS, parent memory quota or authenticated child-PID property is added by this prefix.

No additional general-purpose launcher is requested. Root can use this narrow deadline primitive with the stated external conditions and failure handling, preserving the unchanged 180-second child monitor and actual completion review. This note neither self-admits the command nor verifies those conditions on the current host.
