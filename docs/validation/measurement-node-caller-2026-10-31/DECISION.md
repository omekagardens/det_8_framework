## Positive evidence and decisive gap

The supported `js` declaration provides an **execution timeout**, defaulting
to 30000 milliseconds. This is stronger than the previously assessed
`exec_command` yield timing. `js_reset` documents resetting the JavaScript
kernel and clearing bindings.

Neither declaration supplies a binding from timeout/reset to the required
native invocation's generation-specific entry/nonentry, ordinary terminal
return, committed outcome or bounded owned-invocation cleanup after
cancellation. M-F015 requires ordinary caller return for its O state and
complete generation-bound publication for C. An I/no-C observation may
follow cancellation before entry or after native consumption; it does not
release ownership or authorize a second waiter. The offered timeout/reset
interface provides no documented independent channel resolving that case.

That missing binding is sufficient to reject this proposed caller for the
unchanged contract. A successful ordinary call or a runtime version would
not establish the missing guarantee. No timeout experiment, kernel reset,
native call, scientific calculation or data-body read was performed.
