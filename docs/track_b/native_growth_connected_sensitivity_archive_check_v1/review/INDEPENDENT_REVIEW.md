## Scope and source reasoning

The manifest identifies the published RI122 archive at commit `3027dc6813b95cc57e8637c6598a6b07325074f0`. Its 20,316 bytes are authenticated by the verifier's hardcoded SHA-256 `d3ece15e443eb76a6d99af700470e47b4adb40cdbb690ff219f3393f72f827fc`. Thus schema/scope text and every row, as well as the explicitly checked archive/commit fields, are fixed by exact bytes. There are 117 distinct normalized relative file paths, with integer sizes and lowercase SHA-256 strings. No row is an absolute pathname or has a parent traversal component. All file sizes are below the 8 MiB per-file read bound; the complete published inventory is 25,185,798 bytes.

The verifier refuses missing or unexpected files and nonregular members. It rejects a symlink archive root, directory or file; it checks each member's within-archive ancestry again before opening. The final ancestry selection converts `path.parents` to a tuple before slicing, avoiding version-specific sequence slicing assumptions. An individual read compares pre-open, opened, post-read and final pathname identity/stat observations, bounds the read, and checks exact size and digest. A second inventory comparison follows semantic verification. These are useful stable-checkout consistency checks, not a hostile-filesystem custody guarantee; the README correctly says so. Empty directories do not count as extra *files*, consistent with the stated inventory contract. The implementation never traverses provenance references or imports archived source.

The JSON decoder rejects duplicate keys and nonfinite named constants. The canonical certificate encoder also rejects nonfinite numeric values. The recursive equality routine distinguishes Python types, so booleans cannot masquerade as integers and ordered arrays cannot be reordered. The complete 19-section certificate must be canonical and equal to the auditor's complete reconstructed certificate, including exact canonical bytes. Normal and optimized producer summaries must be byte-identical; the summary identities must bind the certificate/witness digest. The shared saved decision is compared recursively to both producer and root decision records. Producer counts, status and independence boundary, the root status and the three explicitly false broader-claim flags are checked. Full byte authentication covers the other fields of every archived document independently of these semantic checks. This is a comparison of saved objects, not a new calculation of coefficients, roots or probabilities.

Errors from ordinary missing/unreadable files, invalid JSON, changed file contents and mismatched saved data return structured `FAIL` with exit status 1. Success returns an explicitly narrow status and false flags for archived-code execution, independent arithmetic rerun, external provenance traversal, custody re-adjudication and new scientific/physical claims. There are no assertion-dependent acceptance gates in the verifier. Its imports and syntax are standard-library compatible with Python 3.9; actual tests used `/usr/bin/python3` 3.9.6, including the optimized interpreter mode.

## Actual independent checks

One archive copy per source revision was relocated outside the repository; cases reused that copy sequentially. Only the **new** metadata verifier and the reviewer's fabricated test harness were executed or imported. No archived caller, helper, scientific producer or auditor was run or imported. Scientific JSON was decoded only for saved-object/string/type comparison. Every case's output and fabricated failure input remain in the external review directory.

The final-source run completed with exit status 0 in tool result `ecf2fe` and recorded `ALL_INDEPENDENT_ARCHIVE_TESTS_PASS`:

- Four CLI positive cases: relocated default sibling discovery, explicit archive path, optimized Python mode, and the restored archive after all mutations.
- Nine CLI refusal cases: same-length content change, changed length, missing file, extra file, symlink file, symlink directory, symlink archive root, FIFO member and same-length pinned-manifest tampering. Every refusal returned structured failure and exit status 1; the FIFO was rejected before an attempted blocking read.
- Nine direct saved-object/parser refusal cases: nested audit mismatch, nested false-versus-zero mismatch, extra nested audit key, duplicate nested JSON keys, named nonfinite constant, nonfinite exponent at canonicalization, noncanonical certificate bytes, differing producer-summary bytes and false-versus-zero root claim flag.
- One additional direct strictness case checked nested boolean/integer inequality and array order while accepting an equal nested object.

A Python audit hook was installed after importing the new verifier and before calling its `verify()` function. The exact set of opened paths was the adjacent manifest plus the 117 relocated archive files: **118 distinct paths**. No external provenance pathname was opened. A deliberate follow-up reviewer read of the manifest is disclosed. The first review harness wrongly assumed one open event per read and stopped after all its CLI/saved-object tests when it observed 238 rather than 119 events. The exact 118-path set comparison had already passed. This was a reviewer harness assertion error, not a verifier failure. That harness, its per-case logs and `INITIAL_REVIEW_HARNESS_FAILURE.json` are preserved. The corrected harness records event multiplicity and repeats all tests against the final source. No implementation acceptance threshold was weakened.

After the tests, a separate read-only check verified every original archive file against the manifest again, and verified that the three current repository checker files exactly matched the final relocated files tested. It passed in tool result `3600a4`. No repository, original archive, Git or index write occurred in this review.

## Limits and recommendation

Accept the checker as a portable read-only reproducibility improvement for the published snapshot. Its trust root is the reviewed checker/manifest and accepted publication, not an independently authenticated publisher identity. It neither establishes new mathematics nor authenticates historical runtime, execution custody or external evidence. Concurrency observations detect ordinary changes; the stable-checkout prerequisite remains. No new scientific execution admission, probability campaign, measurement qualification or physical claim follows from this result.

Detailed case results are in `final_source/TEST_RESULTS.json`; full open observations are in `final_source/OPEN_TRACE.json`. `TEST_ARTIFACT_INVENTORY.json` binds preserved regular failure artifacts/logs and records nonregular test objects without attempting to read them. The review handoff binds the review, these records, both reviewer harness versions and final source pins. Relocated archives are test copies, not additional accepted scientific evidence.
