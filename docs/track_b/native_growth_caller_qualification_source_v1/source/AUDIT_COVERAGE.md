## Callable API

The main closed driver supplies an already byte-authenticated, freshly imported
unchanged caller module to `run_case(caller, case_id)`. This module never imports
the caller, calls its `main`/`run`, spawns a process, creates a fixture or writes
a file. The driver must use a fresh caller module per case; external runtime
authentication is required before importing even one module. Ordinary internal
cache assignments performed by the subject's own authentic preparation
functions are not harness monkeypatches.

`CASES` contains dictionaries with `id`, `boundary`, `expected`, `input_kind`,
`declared_controls`, `coverage_scope`, and `prerequisite_dependent`. Only the
four deferred cases set the last flag true; the main driver requires explicit
root acceptance of their genuine prerequisites before loading the subject.
Expected results have the exact
`outcome` (`RETURN` or `REFUSED`), exception type, code and message. A returned
direct-boundary report contains those observations and `whole_entry:false`.
Wrong exception type, first reason or return value raises `RuntimeError`; a
bare exception of the expected broad kind is insufficient.

Argument preparation is outside the intended-refusal catcher. If authentic
runtime preparation or a deferred actual binding fails, it escapes as a blocked
or erroneous case; it is never reported as the requested deeper guard passed.
Fabricated dictionaries are transient function arguments only. They are not
accepted identities, frozen cards, real history, tool results or admissions.
