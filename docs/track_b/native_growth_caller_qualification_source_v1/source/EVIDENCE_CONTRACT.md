## 2. Four kinds of coverage, never one blanket pass

Every declared control is tracked separately, in exact RI129 declaration
order and with its four original tuple fields preserved: name, validating
function, required refusal code, intended invalid condition. There are 52
native and 69 audit declarations. Those are inventories, not passed tests.

| Evidence class | What can establish it | What it does not establish |
| --- | --- | --- |
| Whole unchanged entry | Genuine execution of the exact complete caller at its fixed path, command, runtime and admitted conditions; complete outer evidence and independent custody | A deeper branch if an earlier guard refused; successful scientific qualification merely because the outer process ran |
| Direct validator boundary | A genuinely callable function from the exact authenticated source, with disclosed argument construction and exact observed first outcome | Whole-entry execution, authenticity of a synthetic argument, active-card acceptance, or any skipped prerequisite |
| Retained-engine applicability | Exact source equivalence plus specifically scoped accepted historical evidence and compatible caller conditions | Fresh execution of a changed validator, current host conformity or new-target qualification |
| Unavailable deeper coverage | A named unreachable boundary and the precise genuine prerequisite or authority missing | A pass, an executed test, or permission to bypass the prerequisite |

A direct helper may support a component of a declared control without covering
the complete declaration. Record the narrower boundary separately. For example,
rejecting a missing entry through `observed` does not execute `pre_attempt_prerequisites`,
and rejecting a mismatched identity does not execute the completed-review
15/4/71 assertion. A case that never reaches its intended boundary is blocked
or mismatched, not passed. A source location, a saved name/reason tuple and a
future call specification are not an observed execution.

Synthetic in-memory arguments must be labelled as synthetic. They may exercise
ordinary argument-accepting validators after separate admission; they must never
be written into fixed active paths or called historical evidence. No production
constant replacement, monkeypatch, filesystem redirection, extracted/recompiled
guard, source transformation or fabricated accepted predecessor is allowed.
Normal initialization performed by the original preparation function is not a
license to edit its globals. No permissive fallback is permitted.

The implementation's source-defined case inventory is the dispatch boundary:

A later root-owned evidence envelope must preserve all of these fields, whether
inline or as complete pinned subordinate artifacts:

1. Schema/version, packet identity and actual caller identity; ordered case ID,
   original declaration tuple and explicit evidence class.
2. Exact actual call boundary, preparation required, whether the boundary was

3. Input provenance: synthetic arguments versus authenticated actual artifacts;

## 4. Genuine early refusals and external failure custody

The new pre-Attempt gate is read-only but not a transaction. It stops at its
first exception; its tail reobservations are not in a `finally` block. A failure
before `Attempt` allocation has no attempt receipt, no caller-emitted complete
final snapshot and no caller census/cleanup evidence. Do not invent any of them.

For a future specifically admitted whole-entry early-refusal check, root must:

1. Authenticate the exact Python bootstrap, libraries, native/configuration
   dependencies and import namespaces externally **before** launching even the
   qualification helper or caller. Its own earlier imports cannot establish
   that authentication retroactively. Preserve the immutable expected runtime
   manifest; mismatch is a refusal, not permission to update a pin.
2. Preserve the exact pre-admitted command, absolute source path, working
   directory, flags, literal environment and one case condition. Preserve the
   expected complete source/history/dependency and available-prerequisite
   identities externally. For intended absent paths require observed `ENOENT`,
   not a generic read failure or a dangling symlink.
3. Independently observe absence of the selected `mode-01` directory and its six
   possible evidence outputs before dispatch. Observe all three candidate paths
   and any audit `REPORT.json` appropriate to the selected stage. The expected
   set is frozen before dispatch, not selected to match a later result.
4. Retain the real outer tool invocation, raw output and final completion. The
   exact RI129 entry wrappers print `SUPERVISOR REFUSAL: <type>: <message>` and
   exit with integer 2 for a caught pre-entry/preflight exception. Match the
   actual planned first exception/message, not merely the prefix or nonzero
   status. A boolean, an unfinished session, a timeout or an inferred exit is
   not integer 2 with genuine completion. Any tool session must be followed to
   its actual terminal result; saved stdout or an internally caught exception
   cannot replace that result.
5. Independently attempt every external post-observation even after the first
   error: protected sources/premises/history/dependencies, authenticated runtime
   files and namespace/host observations, attempted-path absence and candidates.
   Preserve each successful observation and each error without early truncation.
   Reconcile all available before/after identities and required absences. An
   inaccessible postcheck is a custody failure, not unchanged-by-default.
6. Bind the exact failed invocation/output and external custody into a genuine
   root failure review. Preserve the original refusal alongside any later
   failure; no retry or admission follows automatically. Do not call a refused
   invocation a completed witness/normal/optimized/audit stage.

The absence observations establish only their actual observation times under
the accepted stable-host premise; they are not continuous surveillance or an
OS-adversary proof. A surviving caller process/session or unexplained artifact
invalidates the intended early-refusal evidence. No fabricated receipt is used
to claim a terminal empty child process group when no child was launched.

If a race or later failure consumes an actual Attempt, use the genuine retained
allocated-attempt custody instead. Preserve its complete final postchecks,
monitor/cleanup output and outer nonzero result. Never relabel allocated failure
as an unconsumed early refusal, delete it, overwrite it or silently retry it.

## 6. Load-bearing deeper coverage gaps

metadata. Changing dependency/history/runtime manifest contents while retaining
