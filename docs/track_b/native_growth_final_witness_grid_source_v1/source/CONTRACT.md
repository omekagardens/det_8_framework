# Exact audit contract for the final coefficient grid

This packet prepares a narrow exact audit of whether the unchanged final RI41
coefficient vector lies on the grid of multiples of 1/1000. It contains source
and inert qualification specifications, not an executed audit. No certificate
body has been decoded, no fixture created, and no checker or auditor imported,
compiled, parsed as an AST, probed or run during this preparation.

The research owner must obtain independent source review and separately admit
qualification and any actual audit. This document is not that admission. The
existing programme continues at the handoff boundary; RET alone remains paused.
The measurement lane is separate.

## The exact question and its inherited domain

For each index c from 0 through 108, resolve alpha[c] from the original
certificate's default_alpha, replaced by overrides[str(c)] when that key is
present. The question is whether 1000 times every resolved alpha[c] is an
integer. Every final component must participate, including the last index and
components that use the default. Discovery-rounding prose does not answer this
question.

The literal domain is schema ri41-height-primal-v1, seed interior_a, parent_size
4, potential RI-38 maximal-deletion, and component_order increasing minimum
canonical-local-key. The complete vector has 109 entries. These labels and the
original source define the interpretation; the accepted finite-law and core
ordering premises are inherited, not regenerated by this grid audit.

Both production interfaces have six fixed inputs, with complete path, byte
count and SHA256 identities in SOURCE_IDENTITIES.json under runtime_inputs:

| Role | File and purpose |
|---|---|
| certificate | Original RI41 CERTIFICATE.json, the only coefficient body |
| original_source | Original RI41 check.py, binding the final-vector and index interpretation; read as opaque bytes by the new tools |
| original_manuscript | Original RI41 NORMALIZATION.md, binding the stated finite law and ordering convention |
| assignment | RI159 source-only assignment; identifies the question but does not authorize execution |
| accepted_predecessor | RI157_ROOT_ADJUDICATION.json, binding accepted cap and contrast results |
| accepted_manual_review | RI157 ROOT_MANUAL_REVIEW.md, recording positive core gap and the conditional grid implication |

The fixed original certificate is 2,845 bytes with SHA256
3d966fb20911d630a427ceb777a41539e930d1ba75c3098dcad35e08e4b1d969.
The complete dependency closure retains the historical law linkage. Checking
these six inputs does not replay that closure or independently prove its

## Parsing and complete vector reconstruction

The certificate is bounded by 64 KiB before JSON parsing. UTF-8 is strict;
nesting is bounded by eight container levels. Duplicate object keys are rejected
at every depth, including escape-equivalent spellings. Floating-point and
nonfinite JSON tokens are refused. JSON integer tokens have at most ten decimal
digits; Boolean values are not accepted as integers.

The top object must contain exactly these eight fields: schema, seed,
parent_size, potential, component_order, roots, default_alpha and overrides.
Unknown fields are refused rather than silently ignored. Each domain label and
the integer parent_size must match exactly, with its expected type.

roots must contain exactly 109 distinct triples in strict lexicographic order.
Each member is an integer, not Boolean: the first coordinate lies between 0 and
65535, the second and third between 0 and 15, and every bit of the third is also
in the second. This is a bounded representation-shape check. It does not
reconstruct any graph, determine canonical roots, prove transitivity, or verify
the ratio components. The whole original certificate pin and accepted RI41
verification supply that domain and order linkage. A shape-valid synthetic root
list is never promoted to an actual-law witness.

default_alpha and every override value must be a string containing an unsigned
ASCII integer or a numerator/denominator pair. Each term contains between one
and 64 ASCII digits. Leading zeros within rational terms are allowed; signs,
spaces, decimal points, exponent syntax and Unicode numerals are not. Numerator
and denominator must both be strictly positive. Every declared coefficient is
validated even if an all-overridden vector would leave the default unused.

Rationals are reduced exactly. An unreduced denominator need not divide 1000:
the test is on the represented number, not its spelling. If alpha=n/d in lowest
terms, grid membership is equivalent to d dividing 1000, or to the reduced
denominator of 1000 alpha being one. No float, tolerance or rounding enters.

overrides must be an object with canonical decimal index keys from 0 through
108: no sign, leading zeros, whitespace, negative or out-of-range value.
Every override is consumed exactly once. Missing overrides are valid and select
the default; they are not missing final components. The final result nevertheless
contains every index exactly once in ascending order. A missing root, a missing
result component, or an index outside the domain is a refusal.

The default has a separately reported grid calculation. The global GRID_PASS
or GRID_FAIL depends only on the 109 resolved entries, not on an unused default.
Both an all-default case and an all-overridden case therefore have explicit
qualification coverage. Positivity and lexical validity still apply to the
declared default in both cases.

## Complete intended result

grid_check.py is the production checker. It accepts no command-line arguments,
authenticates all six complete inputs before decoding the certificate, and
rechecks their identities before emitting a result. It writes no file itself;
a separately admitted caller may save its standard output. There is no
production path or pin bypass. Direct pure parsing/reconstruction functions are
qualification boundaries only; they do not confer authentic-witness status.

The exact top-level result keys are schema, status, domain, inputs,
root_order_basis, default, override_indices, components, counts,
off_grid_indices and scope. There are no optional scientific result fields.

- schema is ri159-final-witness-grid-result-v1.
- status is GRID_PASS or GRID_FAIL, computed from the complete final vector.
- domain contains the five literal certificate domain fields, component_count
  equal to 109, and grid_denominator equal to 1000.
- inputs is the six-role identity map above. Each identity contains exactly
  path, bytes and sha256, with the fixed expected values.
- root_order_basis is INHERITED_PINNED_RI41_ACCEPTANCE_NOT_RECONSTRUCTED.
- default contains alpha, scaled_numerator, scaled_denominator and on_grid.
- override_indices is the complete sorted list of explicit override indices.
- components is the ordered list of all 109 records. Each record contains
  index, root, origin, alpha, scaled_numerator, scaled_denominator and on_grid.
  origin is exactly default or override; root is the corresponding original
  triple. alpha is the reduced rational string n/d, including /1 for integers.
  The scaled fields are canonical decimal strings for the numerator and
  denominator of reduced 1000 alpha. on_grid is a Boolean.
- counts contains exactly components, defaulted, overridden, on_grid and
  off_grid, as integers. The first is 109; each appropriate partition sums to it.
- off_grid_indices lists every failing final index, in ascending order.
- scope is GRID_ONLY_NOT_LAW_CAPACITY_W_H30_OR_PHYSICAL_ACCEPTANCE.

No digest alone substitutes for the component records. No field reports an
actual lambda, core contrast, probability, maximum, normalization scale,
capacity sign, W/H30 sign, geometry, gravity or physical acceptance.

## Independent saved result audit

grid_audit.py takes exactly one saved-result path and writes its audit receipt
to standard output. The saved result must be a regular, nonsymlink, absolute
normalized file bounded by 256 KiB. JSON nesting is bounded by twelve levels;
strict UTF-8, duplicate-key rejection and type-sensitive checks also apply.

The auditor does not import the checker or reuse its decoded vector. It
authenticates the same six fixed inputs, independently parses the certificate,
normalizes the rational numbers using integer arithmetic, resolves the default
and every override, and reconstructs the entire expected result. It compares
every key, type, order, root label, component value, scaled value, Boolean,
count, index list, identity and scope field. Comparing only a digest, the
producer's status, or the producer's Boolean flags would fail this contract.
In particular, Python's equality of True and 1 must not hide type drift.

Both tools check stable regular-file identity and complete bytes within each
read, refuse symlink paths, and recheck their inputs before output. The auditor
also rechecks the saved-result file. These are finite snapshot checks, not a
claim to lock files against future changes. Future execution evidence must
retain the admitted source pins, saved result and audit receipt together.

A valid GRID_FAIL is a mathematical result, not a process failure: the checker
exits zero. A saved result that exactly reproduces a valid GRID_FAIL can receive
an audit match with exit zero. Malformed input, identity drift or result
disagreement instead exits two, emits bounded structured refusal diagnostics
on standard error, and emits no success result. An audit match verifies the
calculation and representation; it is not research-owner acceptance.

The auditor receipt has schema ri159-grid-saved-audit-verdict-v1, status MATCH,
reported_grid_status, components_compared equal to 109,
comparison equal to ALL_RESULT_FIELDS_EXACT_TYPE_SENSITIVE_RECOMPUTATION,
boundary, root_order_basis and scope. The direct argument interface uses
boundary DIRECT_ARGUMENTS_NOT_AUTHENTICATED. The production interface uses
FIXED_PIN_SAVED_RESULT_AUDIT and additionally includes inputs, the complete
saved_result path/bytes/sha256 identity, and file_checks equal to
BOUNDED_PRE_POST_READS_NOT_CONTINUOUS_CUSTODY. It does not report a count of
scientific tests performed by this source-preparation packet.

The production audit receipt is bounded by 16 KiB. Checker and auditor refusals
are each bounded by 8 KiB; each uses its own refusal schema, status REFUSED, and
a bounded code and message, with a bounded fallback if needed. The auditor may
also retain later_errors and an explicit omission marker when secondary
diagnostics would exceed its bound; a later failure must not turn an earlier
refusal into success.

Diagnostic persistence cannot be guaranteed if standard error itself fails.
An output-write or flush failure may leave partial standard output. A later
caller must require successful process completion and a complete valid JSON
document; partial capture is never a result. Hard process termination and host
failures likewise establish no success, even without a structured diagnostic.
