## 1. Three outcomes and the premise-conflict boundary

Let the two *routed* original coefficients have difference \(\epsilon\),
and retain the accepted exact threshold

\[
 \epsilon_*=
 \frac{44\cdot1147\cdot3875}{41\cdot126280\cdot508644}
 <1/10000.
\]

An authenticated production result can have these distinct meanings:

| Condition | Required classification | What it does not establish |
|---|---|---|
| malformed, unsupported, unstable or wrongly bound input | INVALID; process refusal exit 2 | Not a small-gap result or a contrary native theorem |
| \(\epsilon\le0\) after otherwise valid interpretation | INVALID, reason `INHERITED_SIGN_CONFLICT` | Not ordinary inconclusive; it conflicts with the retained strict same-law sign |
| \(0<\epsilon<\epsilon_*\) | valid inconclusive; exit 0 | Does not prove the opposite six-entry predicate, \(v>B_6\), an endpoint sign or actual W |
| \(\epsilon\ge\epsilon_*\) | valid sufficient separation; exit 0 | Does not itself prove actual W/H30; it supplies RI189's conditional strict branch rejection |

Equality at \(\epsilon_*\) belongs to the sufficient case. Failure
to reach the simpler threshold \(1/10000\) is not failure of the exact
threshold: \([\epsilon_*,1/10000)\) still suffices. A metadata/hash
match alone establishes none of these arithmetic facts.

The nonpositive case is a premise conflict, not automatically a pathname
or hash mismatch. Those failure causes must remain distinguishable. A
direct-argument result has no original-certificate binding, regardless of
its arithmetic classification or whether its bytes happen to look plausible.

## 2. Boundaries and precedence

The production boundary must authenticate the exact original bytes and
declared byte count before scientific interpretation. A different feasible
vector, an equal-valued reserialization or a one-byte mutation is not the
unchanged original. The complete original hash binds all bytes, including
ignored bounded extra fields. It does not authenticate the running checker,
interpreter, standard library, parent process or admission record; those
remain external root-custody prerequisites.

Consequently a mutated production file reaches the binding refusal, not
a later root/rational/threshold guard. The deeper scenarios below belong
to a separately admitted **direct-argument validator** with explicitly
synthetic, unbound arguments. They must never be credited as a whole-entry
test of genuine unchanged history. No such arguments are created here.

Each isolated scenario assumes every earlier guard is satisfied and all
unmentioned fields are independently valid. A compound scenario must
report its actual first refusal and later independent failures, rather
than crediting a deeper guard that execution never reached. Subject labels
or a forged report cannot substitute for externally observed boundaries.

The checker is not a saved-report auditor unless its concrete source
contains that consuming boundary. Source specs for external report
validation below therefore belong to later admission/custody review, not
to the checker’s present execution coverage.

These facts qualify the P specifications precisely:

- P01 and P03–P07 concern `read_fixed`/`verify_fixed`. In P05, the first
  `Refused` code/message or ordinary exception type survives; a close
  error appears as a later `{stage:close,role,...}` entry. A lone close

- P02 relative or nonnormalized path controls target the direct helper
  `validated_path`, not the no-argument production entry, whose paths

  ancestor/leaf substitutions require separately admitted host evidence.
- P06/P07: `verify_fixed` attempts every one of its nine postchecks after
  an ordinary result or refusal. An earlier cause remains first; if only
  postchecks fail, the first aggregate code is `INPUT_POSTCHECK`. A

  Each read has its own stable metadata window; the wrapper does not
  compare its initial window’s stat tuple against the later window’s
  tuple. A transient mutate/restore entirely between reads is not
  independently detected by these checks. Full-interval custody is

  original hash before decoding.
- P08 reaches `main`’s `ARGUMENTS` refusal before any fixed-input read:
  `this checker accepts no arguments`.
- P09 has only cooperative `COOPERATIVE_DEADLINE` source coverage. The
  checker does not launch, kill, reap or supervise another process. A

  nine-postcheck tail completed; the current descriptor’s `finally`
  still attempts close. Host/kernel stalls and genuine process completion

- P10: `main` checks output size (`OUTPUT_LIMIT`) and the actual returned

- P11: stderr short writes or write/flush exceptions retain exit 2 but
