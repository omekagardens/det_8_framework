## Root bootstrap remains an explicit premise

Before either Python command, genuine root tooling must authenticate the
launcher's interpreter, actual startup suppliers and complete reviewed source.
The launcher cannot retrospectively prove the authenticity of the interpreter
already executing it. A pinned `external_bootstrap` artifact identifies root's
evidence; its bytes or a true boolean cannot establish its genuine origin.

Within that externally authenticated process, this implementation performs
the complete runtime and source observations before RI136 starts. Thus the
ordinary custody mechanism is implemented, while its initial trusted root and
tool origin are stated honestly. The original Darwin kernel, loader and Apple
shared-cache premise remains explicit. Homebrew suppliers receive no exemption.
Observations establish finite before/after matching, not continuous immutability
or resistance to a malicious kernel.

The root/tool layer also owns the real hard stop for uninterruptible host I/O.
Cooperative deadlines and the parent alarm do not make arbitrary filesystem
or `fsync` stalls preemptible. A forced stop leaves partial evidence and missing
observations; it cannot be interpreted as a completed successful collection.

of sampled owned-group RSS, intended 50 ms polling, each census at most 250 ms

Two seconds are reserved inside the
120-second process envelope for cleanup, so ordinary work stops by 118 seconds;
this tightens the usable work interval, not the total limit.

The parent has separate explicit budgets: 60 seconds for authenticated metadata

No child handshake, retry, synthetic sample or hidden limit increase is allowed.
Before/after budgets include their journal closes and summary writes; preparation
card writes are also inside the before budget. The single finalization budget
is shared between child-envelope/process-artifact verification and final
artifact checks/result persistence. Its later part receives only the unspent
remainder, not another 60 seconds.
